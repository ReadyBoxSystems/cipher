<objective>
Build the Inbox screen — the first thing a signed-in user sees. List active conversations sorted by most recent activity, show contact handle/avatar/cipher-preview/relative-time, render the empty state when there are no conversations, and keep the list live via two realtime subscriptions: `subscribeConversationMembers` (new conversations) and per-conversation `subscribeMessages` (timestamp/preview refresh).

Purpose: INBOX-01 through INBOX-05. This screen also registers the `''` (root) route — without it, signed-in users land on a blank app shell.

Output: `screens/inbox.js` (full implementation), `screens/chat.js` (registration stub — Plan 02 fills it in), `app.js` (imports both screens so they self-register at boot).
</objective>

  <action>
Create new file `screens/inbox.js` that registers the `''` (root) route and renders the inbox.

Required imports:
```javascript
import { transport }                from '../transport/index.js'
import * as store                   from '../state/store.js'
import * as router                  from '../lib/router.js'
import { _ago, _strColor, _esc }    from '../lib/utils.js'
```

Register the root view:
```javascript
router.register('', async () => { ... })
```

Inside the handler, do the following in order:

1. Auth/profile guard — if `!store.get('user')` return early with `router.navigate('#/auth')` and an empty cleanup; if `!store.get('profile')` navigate to `#/setup`.

2. Render the topbar shell immediately (before fetching) so the screen does not flash blank:

```html
<div class="screen">
  <div class="topbar">
    <div class="topbar-title">CIPHER</div>
    <div class="topbar-actions">
      <button class="icon-btn" id="inbox-new" type="button" aria-label="New conversation">+</button>
    </div>
  </div>
  <div class="inbox-list" id="inbox-list">
    <div class="center-msg">LOADING...</div>
  </div>
</div>
```

3. Fetch conversations via `await transport.getConversations(user.id)`. For each conversation, fetch the contact via `await transport.getConversationContact(conv.id, user.id)`. Run contact fetches in parallel with `Promise.all` for performance. Save to store:
   - `store.set('conversations', conversations)`
   - For each conv, `store.set('contacts', { ...store.get('contacts'), [conv.id]: contact })` — or build the full contacts map and set once.

   Each `conv` row at minimum has: `id`, `updated_at`. Each contact has: `username`, `display_name` (may be null).

4. Fetch the last message preview for each conversation: `await transport.getMessages(conv.id)` then take the LAST element. Cache in a local map `lastMsgs[convId]`. Run in parallel with `Promise.all`. The preview text must be the encrypted `payload` truncated to a short string for display. Per D-04: we cannot decrypt server-side — show the raw base64 `payload` substring (first 40 chars) as the cipher-encoded preview. The `.conv-preview` CSS already handles `text-overflow: ellipsis`. If no messages exist for a conversation, preview is empty string and the row's time falls back to `conv.updated_at`.

5. Render the list. If `conversations` is empty (length 0), replace `#inbox-list` content with the empty state:
```html
<div class="center-msg" style="padding:48px 24px;text-align:center">
  <div style="font-size:13px;letter-spacing:0.1em;color:var(--text);margin-bottom:8px">NO MESSAGES YET</div>
  <div style="font-size:11px;letter-spacing:0.1em;color:var(--text-dim)">TAP + TO START A CONVERSATION</div>
</div>
```

   Otherwise, for each conversation render a `.conv-row` with:
   - `data-conv-id="${conv.id}"` attribute on the row for click delegation
   - `<div class="avatar" style="background:${_strColor(contact.username)}">${(contact.display_name || contact.username || '?')[0].toUpperCase()}</div>`
   - `<div class="conv-info"><div class="conv-name">@${_esc(contact.username)}</div><div class="conv-preview">${_esc(previewText)}</div></div>`
   - `<div class="conv-time">${_ago(lastMsg ? lastMsg.created_at : conv.updated_at)}</div>`

   Sort conversations by the timestamp used for `.conv-time` (latest message OR `conv.updated_at`) descending so that newly-active conversations float to the top per INBOX-01.

6. Wire click handlers via event delegation on `#inbox-list`:
```javascript
listEl.addEventListener('click', (e) => {
  const row = e.target.closest('.conv-row')
  if (row) router.navigate('#/chat/' + row.dataset.convId)
})
```
   Wire the `+` button:
```javascript
newBtn.addEventListener('click', () => router.navigate('#/new'))
```

7. Realtime subscriptions per D-06:
   - `const unsubMembers = transport.subscribeConversationMembers(user.id, async (member) => { ... })` — when a new conversation_member row arrives for this user, re-fetch conversations + contacts + last messages and re-render the list (same logic as initial load — extract into a `renderList()` helper to avoid duplication).
   - For each conversation, open a `subscribeMessages(conv.id, (msg) => { ... })` subscription that updates `lastMsgs[msg.conversation_id]` and re-renders the list. Store all unsubscribe functions in an array `unsubs`.

8. Return a cleanup function that:
   - Calls every function in `unsubs`
   - Calls `unsubMembers()`
   - Removes the click and `+` listeners (or rely on the next innerHTML overwrite — but explicit removal is safer)

The full screen is one IIFE-shaped handler. Keep it under ~180 lines. Mirror the structural patterns of `screens/settings.js` (innerHTML write, querySelector wiring, return cleanup).
