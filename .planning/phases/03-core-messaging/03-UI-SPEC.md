## Typography

Exactly 4 declared sizes for this phase:

| Role | Size | Weight | Line Height | Letter Spacing | Usage |
|------|------|--------|-------------|----------------|-------|
| Body | 13px | 400 | 1.55 | 0.02em | Bubble text (`.bubble-text`), field inputs, compose input |
| Label | 11px | 400 | 1.4 | 0.04–0.15em | Conv preview, lock label, button text, tab text, error messages, check label, "MORE" expand link |
| Meta | 10px | 400 | 1.4 | 0.04–0.06em | Conv time, message timestamp, logo-by line |
| Title | 12px | 400 | 1.4 | 0.04–0.5em | Conv name (12px), topbar title rendered at 11px + 0.3em tracking (falls within Title range) |

Notes:
- Message timestamps (`msg-time`) render at 10px — treated as the Meta token, not a separate declared size. 9px is not used; if `style.css` has 9px for msg-time, update to 10px for consistency.
- The 15px setup screen title belongs to Phase 2's typography contract and is not declared here. Phase 3 does not render any setup screen elements.
- All text uses `var(--font)` — JetBrains Mono monospace stack. Uppercase via `text-transform: uppercase` on interactive labels. Do not introduce a sans-serif or different font.

Phase 3 specific:
- Cipher-encoded text in bubbles: 13px (Body token), `var(--text)`, 1.55 line-height — the encoded glyphs, runes, Morse ARE the content
- "MORE" expand link: 11px (Label token), `var(--accent)`, `text-transform: uppercase`, `letter-spacing: 0.1em`
- Inline error in compose bar: 11px (Label token), `var(--danger)`, same pattern as `.error-msg`

Source: `style.css` measured values + CONTEXT.md D-05.

**Accent reserved for:**
- Topbar title text (`.topbar-title`)
- Logo glyph and logo name (`.logo-glyph`, `.logo-name`)
- The `@` symbol in handle input (`.at-sym`)
- Active tab state (`.tab.active` — text `--accent-hi`, background `--accent-dim`)
- Button fill/text: `.btn`, `.btn-sm`, `.send-btn` (amber dim background + amber text)
- Focus ring on field inputs: `border-color: rgba(212,168,67,0.4)` on `:focus`
- Lock glyph color (`.lock-glyph`) — opacity 0.45
- Cipher-encoded text visible in inbox preview row: NOT accented — stays `var(--text-dim)` to remain subtle
- "DECODE MESSAGE" button (`.btn-sm`) label text
- "MORE" expand link text
- Checkbox `accent-color`
- Invite link text color

**Accent is NOT used for:**
- Regular body text
- Conversation names
- Timestamps
- Message bubbles from other users
- Error states (use `--danger`)

## Component Inventory (Phase 3 Specific)

These are the markup structures the executor must emit. All CSS classes already exist in `style.css`.

### Inbox Screen (`.screen`)

Primary focal point: `.inbox-list` — this is the main content region; all other elements are chrome around it.

```
.topbar
  .topbar-title — "CIPHER"
  .topbar-actions
    .icon-btn[aria-label="New conversation"] — "+" (navigates to #/new stub)

.inbox-list
  .conv-row (×N, tappable → #/chat/:id)
    .avatar (colored via _strColor)
    .conv-info
      .conv-name — @handle
      .conv-preview — cipher-encoded last message text (1 line, ellipsis)
    .conv-time — relative time via _ago()

  .center-msg (empty state — shown when no conversations)
```

### Chat Screen (`.screen`)

Primary focal point: `.messages-list` — this is the main content region; topbar and compose bar are persistent chrome.

```
.topbar
  .topbar-title — @handle of contact
  .topbar-actions
    .icon-btn[aria-label="Back to inbox"] — "←" back to inbox

.messages-list
  .msg-wrap.mine / .msg-wrap.theirs (×N)
    .bubble.mine / .bubble.theirs  ← tappable if locked
      [locked state]
        .bubble-text — cipher-encoded text (with CSS gradient fade if overflows)
        .bubble-more — "MORE" link (shown when text exceeds 5 lines; hidden after expand)
      [decoded state]
        .bubble-text — plaintext (no flip element rendered when keep=true)
    .msg-time — timestamp

.decode-panel (shown when card is flipped / overlay fallback active)
  .panel-row
    .field-sm[type=select] — cipher type
    .field-sm[type=text] — key input
    .btn-sm — "DECODE MESSAGE"
  .panel-row
    .check-label
      input[type=checkbox] — keep decoded toggle
      "KEEP DECODED FOR ME"
  .error-msg — inline decode error

.compose-bar
  .compose-meta
    .field-sm[as=select] — cipher type
    .field-sm[as=input]  — key field
  .compose-row
    .compose-input[textarea] — message text
    .send-btn[aria-label="Send message"] — "→"
```

**Icon-only buttons require `aria-label`:** Any button or interactive element that renders only a glyph ("+", "←", "→") must carry an `aria-label` attribute as shown above. The label text must be plain English, not a symbol or code name.

### Card Flip / Overlay Fallback

- **Primary (Android Chrome):** CSS 3D flip on `.bubble` — `transform-style: preserve-3d`, `backface-visibility: hidden`, `transition: transform 0.45s ease`. Card front shows cipher text. Card back shows decode inputs inline (replaces `.decode-panel` bottom dock when flip is active).
- **Fallback:** If 3D flip does not render, lock-icon button (`.icon-btn` size, amber lock glyph) appears on bubble. Tapping opens `.decode-overlay` — a fixed full-screen overlay (`position: fixed; inset: 0`) over the messages list, containing the same decode form fields. Background scrim: `rgba(7,7,7,0.88)`.

Source: CONTEXT.md D-02, D-05.

### Bubble Gradient Fade (D-05)

Applied to `.bubble-text` when cipher-encoded content exceeds 5 lines:
- CSS property: `mask-image: linear-gradient(to bottom, black 60%, transparent 100%)`
- Fade height: covers bottom 40% of the clipped container (max-height: `calc(5 * 1.55 * 13px)` ≈ 101px)
- "MORE" link sits below the fade, `color: var(--accent)`, `font-size: 11px`, `text-transform: uppercase`
- On expand: remove `mask-image` and max-height; "MORE" changes to nothing (hidden)
- Animation: `transition: max-height 0.25s ease`

Source: CONTEXT.md D-05 + Claude's Discretion.

### Lock Pulse Animation (CHAT-11)

One pulse on the lock glyph when an incoming locked message arrives. Not continuous.

```css
@keyframes lock-pulse {
  0%   { opacity: 0.45; }
  50%  { opacity: 1; color: var(--accent-hi); }
  100% { opacity: 0.45; }
}
.lock-glyph.pulse {
  animation: lock-pulse 0.6s ease forwards;
}
```

Class `.pulse` added on message insert, removed after animation ends (`animationend` event).

## Interaction States

| State | Trigger | Visual |
|-------|---------|--------|
| Conv row tap | Touch/click | `background: var(--surface)` (`:active` already in CSS) |
| Bubble tapped (locked) | Touch/click | Card flips 180° (0.45s) or overlay appears |
| Only one flip at a time | Second bubble tapped | First card flips back before second flips |
| Decode success | Correct key entered | Card flips back; bubble-text shows plaintext |
| Decode failure | Wrong key | `.error-msg` shows "WRONG KEY — CHECK CIPHER AND KEY"; field shakes (no alert) |
| Keep decoded on | Checkbox checked | Future messages in conversation render as plain bubbles; no flip element rendered |
| Optimistic send | Send tapped | Message appended to list immediately with amber dim background |
| Send failure | Transport error | Optimistic message removed; `.error-msg` appears in compose bar |
| Realtime message | Incoming message | Appended to messages-list; lock-pulse plays on lock-glyph once |
| Bubble overflow | Cipher text > 5 lines | Gradient fade applied; MORE link shown |
| MORE tapped | Tap MORE | Bubble expands to full height (0.25s); MORE hidden |
| Field focus | Any input focused | `border-color: rgba(212,168,67,0.4)` (already in CSS) |

## Realtime Architecture (Design Contract)

The executor must wire subscriptions at the screen level per D-06:

- `screens/inbox.js` subscribes: `subscribeConversationMembers` (new conversations) + cross-conversation `subscribeMessages` (inbox timestamp refresh)
- `screens/chat.js` subscribes: `subscribeMessages` scoped to `convId`
- Both screens return a cleanup function; router calls cleanup before mounting next screen
- Deduplication: on realtime message echo after optimistic send, skip insert if message ID already present in local state
